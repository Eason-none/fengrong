# 设计：每日卡片"换一批"边界修复

## Context

现状（`src/components/DailyCard.vue`）：`refreshCount` 累计计数，≥3 后按钮替换为固定关怀文案；`doRefresh` 在抽不出新批（`next.length === 0`）时保留当前批但仍 `refreshCount++`。设计原意（product_handoff §5.1.1 v4）是把"反复刷新"解读为疲惫信号并以关怀收尾，同时防止"换一批"沦为内容选择器。stress test 暴露：计数不区分"空手换"与"领了再换"，见底时按钮静默失效还偷扣计数。

相关现成设施：
- "丰容探索"是 tabBar 页（`pages/explore/explore`），`uni.switchTab` 可达
- "三件幸福小事"在主页有现成对话流（`index.vue` 的 `openThreeGoodThings()`），three-good-things spec 已声明"主页/日推卡片"双入口
- DailyCard 是主页的全屏 overlay，通过 emit 与 index 通信

## Goals / Non-Goals

**Goals:**
- 计数只捕捉设计原意中的信号：连续空手换批 = 可能疲惫
- 池子见底成为显式状态：不扣计数、明说到底，与疲惫态区分
- 疲惫态从"到此为止"变为软引导：丰容探索 / 记幸福小事两个轻出口

**Non-Goals:**
- 不改 `getDailyTaskCandidates` 抽取算法与场景匹配规则
- 不动"领取未完成条目永久排除、无重置路径"的池子机制（已知边界，单独议题）
- 不做囤任务抑制（本次决策：领取即胃口信号，不设累计上限）
- 不改卡片重开时 `refreshCount` 随组件重建归零的既有行为

## Decisions

**D1 计数语义：claim 归零，而非"本批领过则该次不计"**
`claim()` 里直接 `this.refreshCount = 0`。语义即"连续空手换批次数"，实现是一行；"该次不计"需要额外记录本批领取状态，语义相同但状态多一份。领取后无限换的尽头是见底态（去重保证批批新条目，池子有限），行为自然收敛，不会退化成无限选择器。

**D2 见底态：单向 flag，优先级高于疲惫态**
`doRefresh` 中 `next.length === 0` 时置 `poolExhausted = true`，不递增计数、保留当前批。渲染优先级：见底态 > 疲惫态 > 换一批按钮——"没得换"是硬事实，压过"你可能累了"的推断。见底后领取不会让池子回填，flag 无需回退。

**D3 疲惫态软引导：emit 事件，index 承接**
DailyCard 新增 emit `go-explore` / `open-three-good-things`；index 侧统一"先 `closeDailyCard()` 再跳转"——`uni.switchTab('/pages/explore/explore')` 或调用现成 `openThreeGoodThings()`。不在 DailyCard 内直接导航：卡片是 overlay，关闭责任在宿主页，且 `openThreeGoodThings` 的会话续用/新建逻辑不该复制第二份。

**D4 疲惫态仍锁死换批（当次卡片会话内）**
软引导替换的是语气和出路，不是解除限制——解除就违背"推送而非选择"原则。用户从主页常驻入口重开卡片时计数随组件重建归零，已有的"下次再看"通道保留。

**D5 文案（须过 Gate 0，实现时定稿）**
- 疲惫态（示意）："换了好几批了，今天没遇到想做的也没关系。可以去图鉴里随便逛逛，或者说说今天有什么幸福的小事。" + 两个轻入口："去丰容探索看看" / "记一件幸福小事"
- 见底态（示意）："今天能给你的都在这儿啦，改天再来看看。"
两态文案不得复用：见底对象可能是刚领完全部任务的热情用户，"没找到想做的"语境不成立。

## Risks / Trade-offs

- [领取后计数归零，用户可反复"领 1 个换 1 批"高频翻池] → 池子按已领+当前批去重，翻到尽头即见底态；单日可翻完的池量本身有限（70 条中场景可达子集），可接受
- [疲惫态两个出口把"放下手机休息"的原关怀弱化为导流] → 文案保留"没找到也没关系"的接纳前置，出口是"可以"而非"快去"；Gate 0 审文案时重点核对语气
- [见底态与"全领取"叠加时用户仍想要更多] → 属于池子重置机制议题（Non-Goal），见底文案先把状态说实话
