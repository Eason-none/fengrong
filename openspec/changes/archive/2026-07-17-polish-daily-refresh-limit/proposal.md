# 每日卡片"换一批"边界修复

## Why

内测 stress test 反馈暴露了"换一批最多 3 次"的两个边界错位：(1) 计数不区分"空手换批"（疲惫信号，限制的本意）和"领了还想再领"（胃口信号），热情用户每批都领仍在第 3 次被锁死，且兜底文案"没找到今天想做的也没关系"对刚领了一堆任务的用户完全说反；(2) 可抽池见底时点"换一批"界面纹丝不动、计数还被白扣一次，用户感知为按钮坏了。另外原疲惫态是生硬的"到此为止"，产品希望改为软引导——给用户指向丰容探索图鉴或"三件幸福小事"记录，而不是系统性拒绝。

## What Changes

- "换一批"计数语义从**累计次数**改为**连续空手次数**：本批中发生过领取，则计数归零；连续 3 次未领取就换批，才进入疲惫态
- 新增**池子见底态**：抽不出任何新条目时不消耗计数、当前批保留，"换一批"按钮原位替换为到底说明文案（与疲惫态文案区分）
- 疲惫态从纯文案升级为**软引导**：保留关怀语气，并提供两个轻入口——跳转"丰容探索"tab 逛图鉴、拉起"三件幸福小事"记录对话（复用现有入口机制，非新流程）
- 所有新增/改动文案须过 Gate 0（content_principles.md）

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `daily-card`: 补充"换一批"刷新机制的需求（此前仅存在于 product_handoff §5.1.1 与实现，未落主 spec）：连续空手计数规则、池子见底态、疲惫态软引导（丰容探索 + 三件幸福小事双出口）

## Impact

- `src/components/DailyCard.vue`：refreshCount 计数逻辑（claim 归零）、doRefresh 见底分支（不计数）、疲惫态/见底态两块 UI 与新事件（`go-explore`、`open-three-good-things`）
- `src/pages/index/index.vue`：承接两个新事件——关卡片后 `uni.switchTab` 到丰容探索 / 调用现有 `openThreeGoodThings()` 拉起记录对话
- `three-good-things` 能力不需改动：其 spec 已声明"主页/日推卡片"双入口
- 归档时同步更新 `product_handoff.md` §5.1.1（刷新次数限制一节）
