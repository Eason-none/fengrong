# polish-beta-feedback-2 · 设计

## Context

第二轮内测反馈（2026-07-16）分诊后拍板的 7 项修复/增强。根因已在代码里逐条核实：

- 华为图鉴单列：`CollectionGrid.vue` 用 `width: calc(50% - 10rpx)` + flex `gap`，华为/鸿蒙内核对「calc 里 % 混 rpx」和 flex gap 支持不稳，calc 失效后卡片塌成内容宽的一竖排。
- 图标缺字/走形：`⚙`（NavBar.vue，U+2699 无 emoji 变体符→华为按文本字形渲染）、`📷`（ChatView.vue，部分机型 emoji 字体缺字形→空白）。同页的手记册图标是 CSS 绘制，从未出问题——病根是依赖系统字体。
- 呼吸不可退出：按钮区 `v-if="!started"`，点了「我准备好了」后跳过按钮消失，误点用户被锁约 38s（两轮 4-7-8）。
- 节奏点不匀速：`startBeats()` 用一串独立 setTimeout，页面常驻光晕/圆环 CSS 动画在低端机挤占主线程，定时器漂移。
- 海浪声失败：1.2MB mp3 打在主包、`/static/...` 本地路径，真机 `onError` 静默降级所以无感知坏掉；同时占主包体积（上线前红线）。
- 分享卡照片糊：导出侧是满 dpr PNG 无损（文字底纹清晰佐证）；源头是照片落库压缩长边 900px/JPEG q60。卡片照片区 ≈300 逻辑px × dpr3 ≈ 900 物理px，源图 1:1 但 q60 压缩痕迹可见。
- AI 慢：qwen3.7-plus 是思考型推理模型 + 小程序端非流式（云函数一次性返回）——思考 token 全程干等；云函数冷启动再加 1~2s。

约束：仅 mp-weixin 端；「不打扰/静默降级」的既有产品原则不动；分享卡卡面红线（无数字）不涉及。

## Goals / Non-Goals

**Goals:**
- 图鉴网格、功能图标在所有在售机型（含华为/鸿蒙）正确显示。
- 呼吸引导可随时退出；节奏点匀速；海浪声真机可播且主包瘦身 1.2MB。
- 新照片在分享卡上无可见压缩痕迹。
- 主对话首响从 10~15s 降到 3~5s，不换模型不降质。
- 图鉴 emoji、叶子标语随机两项体验增强落地。

**Non-Goals:**
- 不做真流式（云托管 SSE + 备案域名成本高，等待文案池已缓冲体验）。
- 不换 LLM 厂商/模型。
- 不救存量 900px/300px 旧照片（原图从不落库，无从回升）。
- 心情系统（⑧）、社交空间（⑨）明确挂起，另行讨论。
- H5 端不适配（2026-07-15 起停维护，但 imageCompress 的 H5 分支常量顺手同步，避免两分支参数漂移）。

## Decisions

### D1 双列网格：width 48% + space-between，不用 calc 不用 gap

`collection-grid` 容器 `justify-content: space-between`，卡片 `width: 48%`（余 4% 作列距），行距用 `margin-bottom: 20rpx` 补。放弃 calc 与 gap 是因为它们正是兼容性事故点；48% 的视觉列距（~28rpx）与原 20rpx 差异肉眼不可辨。
- 备选：grid 布局——小程序端 display:grid 兼容性同样存疑，排除。
- 备选：只修 calc 保留 gap——gap 本身也是可疑点，一次修干净，不留第二次真机回归。
- 注意：卡片数为奇数时 space-between 不会异位（最后一行单卡靠左，符合预期）。

### D2 功能图标：CSS 绘制，与手记册线条书同语言

⚙ 换成 CSS 画的线条齿轮或等价"设置"隐喻（几条横线的调节杆更易画准），📷 换成线条相机（圆角矩形 + 镜头圆）。与 `.dn-book` 同一套线条风格（1~2px 描边、`--c-subtle` 色）。
- 备选：emoji 加 U+FE0F 变体符——只解决"文本字形"问题，解决不了缺字形和跨厂商画风不可控，排除。
- 备选：内置 PNG/SVG 图片——多资源文件、要管多倍图；CSS 绘制零资源且已有成功先例（手记册图标），优先。
- 用户原建议是"两个都做成 emoji"，已沟通改判：②的病根恰是 emoji 依赖系统字体，绘制才是全机型解。

### D3 呼吸退出：进行中常驻「先不做了」，走 skip 同一清理通道

started 后在环境音开关旁（或其下）显示低调文字入口「先不做了」，点击即调用既有 `skip()`（clearTimers + finish 渐淡 + 音频淡出）。视觉权重低于环境音开关——它是给误点者的安全门，不是给认真呼吸者的干扰项。
- 备选：仅前 N 秒可退出——多一个状态机分支，且"被锁"体验只是缩短没消除，排除。

### D4 节奏点：CSS animation-delay 声明式点亮

每颗点固定挂 `animation: beat-light 0.4s both`，第 k 颗 `animation-delay: (k-1)s`；JS 只负责在阶段开始时重置节奏点组（换 key 重挂 DOM 触发动画重放），不再每秒发 setTimeout。动画由渲染层调度，主线程卡顿不影响节奏均匀性。
- 既有 spec 承诺（polish-beta-feedback delta「呼吸阶段节奏可感」：每秒柔和点亮、跳过无残留定时器）全部继续满足——实现方式变化不触碰该 requirement 文本。
- 备选：单 interval + 时间戳校正——仍受 setTimeout 调度延迟影响，只是漂移小些，不如声明式彻底。

### D5 海浪声：微信云存储 + getTempFileURL，结果缓存

mp3 上传云存储（一次性部署步骤），代码持有 fileID 常量；起播前 `wx.cloud.getTempFileURL` 换临时 https URL，结果连同过期时间缓存进 storage（临时 URL 有效期内直接复用，过期重取）。任何一步失败→维持静默降级为无声引导（既有原则）。主包删除 mp3，瘦身 1.2MB。
- 备选：保留本地文件、只改路径写法——失败根因未确诊（真机 errCode 未拿到），改路径是赌；云存储 https 是标准可靠路径，且主包瘦身本来就是上线前要做的，一步到位。
- 备选：fileID 直接喂 InnerAudioContext——`src` 不接受 cloud:// 协议，必须换 URL。
- 取 URL 是异步步骤，插在「我准备好了」点击与起播之间：淡入本来就有 2s 缓冲，几百 ms 的取 URL 延迟无感；为保守起见可在组件挂载时预取。

### D6 照片压缩提档：长边 1200px / JPEG q80 起步，真机压测定档

`THUMB_MAX_EDGE` 900→1200（给 dpr≥3 的大屏留余量），mp 端 `quality` 60→80，H5 分支 `toDataURL` 0.7→0.8 同步。压缩痕迹的主因是 q60（900px 已足够 1:1），提 q 是主刀，提边长是余量。真机压测两项验收：卡面照片近看无块状伪影；单张体积 ≤450KB。
- 存储影响：10MB 预算从 ~60 张降到 ~25 张，接受——分享卡画质优先，超限时既有「静默裁图」降级兜底；外置层同图去重仍有效。
- 存量旧图不迁移不回升，如实保持（spec delta 中已写明）。

### D7 延迟：enable_thinking:false 透传，模型不换

`qwen.js` 小程序分支请求体加 `enable_thinking: false`；`llmProxy` 云函数入参从 `{target, model, messages}` 扩展为透传额外字段（白名单式：`enable_thinking` 等已知参数，不盲传整个 event，避免客户端可注入任意上游参数）。deepseek 摘要链路不加（deepseek-v4-flash 本身无思考开销，且摘要是后台异步、不在等待路径上）。
- 质量评估：本场景是 ≤3 句的见证式回应，质量由 system prompt 主导，深度推理增益趋零；真机对比验收，不满意回滚 = 删一个参数。
- 备选：换 qwen-flash——降质风险真实存在（用户明确担忧），排除。
- 备选：云托管 SSE 真流式——需备案域名 + 架构改动，投入产出不成比，列为 Non-Goal。
- 云函数需重新部署（部署步骤入 tasks）。

### D8 图鉴主题图标：Twemoji PNG 内置（2026-07-16 两轮修订后定稿）

演进：字符方案（第一代 Unicode 安全集 emoji 放标题旁）→ 真机二验证明**任何 emoji 字符都不可靠**（用户机型全部缺字/走形）→ CSS 线稿样稿被用户否决 → 定稿 **emoji 图片化**：Twemoji 开源 PNG（每张 ~1KB，8 张 ~7.5KB）打进 `static/icons/tujian/<collection_id>.png`，`CollectionGrid` 以 `<image>` 展示在卡片右上角**原状态点「·」的位置**（状态点被取代）。状态三档：locked=降透明 0.4（mp 端 `filter: grayscale` 不可靠，不用）、active=彩色、completed=**金色圆底**（`--c-accent`，用户定稿：不加金环）。标题旁 emoji 字符字段已回滚（library.js 数据层无感知，路径按 id 拼）。Twemoji CC-BY 4.0 署名已入隐私政策附注。换图=换 PNG 文件一步，不动代码。

### D9 叶子标语：onShow 随机起点，刮风轮换不变

`lineIndex` 初始化从「当日日期种子」改为首页每次 `onShow` 时 `Math.floor(Math.random() * FLYLEAF_LINES.length)`；`blowWind()` 的 +1 轮换与淡出淡入动效不动。会话内点叶子的连续性保留（随机只发生在进页时刻）。
- 原「每日固定一句」是 2026-07-13 定稿的"采集标注"叙事；本次经用户拍板改为进页随机（surprise 优先），折中保留了刮风机制。
- 注意 onShow 在同一次会话内可能多次触发（从对话/分享返回），意味着"回到首页就换句"——这正是用户要的"每次点开都不同"，按此实现；若真机体感换得太频繁，退一档到"仅冷启动随机"是一行改动。

## Risks / Trade-offs

- [48% 双列在华为上仍异常（根因不是 calc/gap）] → 该修法把两个可疑点全部移除，若真机仍复现则说明是更深的内核问题，需借用户的华为机型抓真机 debug——本批先按最大概率修。
- [云存储临时 URL 过期边界（缓存的 URL 恰好在起播瞬间失效）] → 缓存过期时间提前量取 1 天以上；失败路径本就静默降级，最坏损失是一次无声引导。
- [q80/1200px 单张体积超预期（图片内容差异大）] → 真机压测定档；若普遍 >450KB 降回 q75 或 1100px，验收标准是卡面观感不是参数本身。
- [enable_thinking:false 后回复质感下降] → 真机 A/B 对比验收；回滚成本 = 删一个参数 + 重部署云函数。
- [归档顺序错乱（本变更先于 polish-beta-feedback 归档会让 delta 基线错位）] → proposal 已写明依赖；归档时按序执行。
- [ChatView 相机图标改绘制后与输入框布局微错位] → 图标容器沿用原尺寸盒（只是内容从字符变绘制），真机过一眼。

## Migration Plan

1. 代码全部落地后：mp3 上传微信云存储（控制台一次性操作），fileID 写入常量。
2. llmProxy 云函数重新部署（透传参数）。
3. 主包删除 `static/audio/breathing-sea.mp3`，构建确认包体积下降。
4. 真机回归重点机型：华为（网格/图标/海浪声）、iPhone（无回归）、低端安卓（节奏点匀速）。
5. 回滚：各项互相独立，单项回滚不影响其余；enable_thinking 回滚需重部署云函数，其余均为前端版本回退。
