# Proposal: add-instant-mood-fit

## Why

时刻推断（add-instant-moment-fit）解决了即时抽取对**外部时刻**（几点、工作日、天气）的盲区，但对**内部时刻**——用户此刻的心情——仍然一无所知：烦躁的人被派去菜市场买不认识的菜，任何一次这样的错配都会把入口读成"随机老虎机"（内测反馈⑧原话方向：心情不好时推深呼吸、听歌类更实用）。心情推不出来，只能问；但问必须是白送的增益而不是新增的门槛，否则毁掉即时入口"零决策"的立身之本。

## What Changes

- **心情选择小窗（可选、不挡路）**：点击"现在就来一件"后弹出轻量小窗——"你现在的心情是怎样的"，四个 chip：**沮丧 / 烦躁 / 无聊 / 活力**，外加一等公民的跳过项（"都不是，随便来一件"）。跳过或不选走现行抽取链路，行为与本变更前完全一致；选了心情才叠加软优先。
- **心情→客观属性映射（映射表在代码里，内容不打心情标）**：心情是主观的、内容是客观事件，两侧各自客观化——
  - 无聊 → 新鲜尝试类条目优先（B 类"熟悉载体 × 一个陌生变量"型）
  - 沮丧 / 烦躁 → 低启动成本 + 感知舒缓类优先，且小窗内提供**呼吸引导直通入口**（复用"静一下"覆盖层，不新造呼吸形态）
  - 活力 → 出门 / 移动类高启动成本条目优先（趁能量在，把平时抽不动的抽出来）
- **内容侧一个客观可选字段**：每日任务池条目新增 Gate 0 类别标（A 类感知重定向 / B 类新鲜尝试），客观可审计；启动成本不加字段，直接由 `scene_tags` 派生（就地可做 vs 需出门/移动），零打标成本。
- **机制复用 moment-fit**：心情软优先叠加在时刻推断候选之上，同一套软优先 + 回落链，错配最坏结果只是退回无心情偏好的抽取，任何条目不因心情而抽不到。
- **纪律**：心情选择不持久化、不进 analytics 载荷、不形成任何情绪记录或统计（不是情绪追踪 App，同"数值不可见"原则）。
- 配套内容原则已先行落地（2026-07-16）：content_principles.md B 类新增通用写作公式「熟悉载体 × 一个陌生变量」。

仅 mp-weixin 端（H5 已停维护）。

## Capabilities

### New Capabilities

（无——心情适配是即时入口交互与抽取规则的演进，不构成独立能力。）

### Modified Capabilities

- `instant-task`：「主页提供即时入口」requirement 从"点击后无任何中间选择步骤"改为"点击后先出可选心情小窗（跳过一等公民）"；「即时任务抽取规则」在时刻推断 + moment 软优先之上叠加心情软优先层；沮丧/烦躁小窗内提供呼吸直通入口。
- `daily-task-content`：条目 schema 新增可选字段（Gate 0 类别标 A/B）及其打标写作要求；明确无标条目行为（不参与心情软优先，永远可被抽中）。

> 依赖说明：`instant-task` 的现行主 spec 文本尚未包含 `add-instant-moment-fit` 的 delta（该变更待真机验收归档）。本变更的 delta 以其归档后的 spec 状态为基线，**归档顺序须为 add-instant-moment-fit 在前、本变更在后**。

## Impact

- **前端**：`src/pages/index/index.vue`（即时入口点击后插入心情小窗、`pickInstantTask()` 接入心情软优先、沮丧/烦躁直通"静一下"覆盖层）；心情小窗为新增轻组件或页内实现。
- **逻辑层**：心情→属性映射表与启动成本派生（落点跟随 `momentInference.js` 的纯函数风格，可同文件或新建 `moodMapping.js`）+ 对应断言脚本。
- **内容**：`src/content/daily_tasks.json` 全池 69 条补 Gate 0 类别标（客观分类，一眼可判）。
- **文档同步**：`content_principles.md` §五 字段表补新字段；`manual_acceptance_checklist_v2.md` 补验收节。
- **不触碰**：每日卡片候选逻辑、DailyTaskPool 与完成事件数据结构、日记链路、呼吸引导内部行为（breathing-entry spec 不改，直通只是复用既有覆盖层入口）、提醒系统。
- **不新增**：网络请求、持久化键、analytics 事件。
