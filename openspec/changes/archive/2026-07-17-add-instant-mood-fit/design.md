# Design: add-instant-mood-fit

## Context

即时抽取现状（add-instant-moment-fit 落地后）：`InstantFlow.vue` 状态机 card → invite → chat；抽取先经 `inferMomentScenes`（时段桶×工作日/周末 与档案求交，空则回落）取候选，再经 `preferMomentCandidates` 软优先排序取首条。软优先语义：打标条目全部亲和标相容才置前，无标中性，无匹配原样返回——错配最坏退回普通抽取。

心情是这套推断覆盖不到的"内部时刻"：推不出来，只能问。设计约束（对话中已拍板）：问必须可跳过且不挡路；内容侧不打主观心情标；不形成情绪记录。

## Goals / Non-Goals

**Goals:**

- 即时入口获得心情维度的适配能力，且不选心情时行为与现状完全一致
- 心情→内容的映射全部落在客观、可审计的属性上（Gate 0 类别 + 场景派生的启动成本）
- 沮丧/烦躁用户获得呼吸引导直通路径（复用"静一下"覆盖层）
- 复用 moment-fit 的软优先+回落安全模型，零新增空态风险

**Non-Goals:**

- 不做情绪记录、趋势、统计（不是情绪追踪 App）
- 不影响每日卡片候选逻辑（用户有选择权，方差可接受）
- 不改呼吸引导内部行为（breathing-entry spec 不动）
- 不做 H5 适配（已停维护）
- 不为心情新增网络请求、持久化键或 analytics 事件

## Decisions

### D1 心情小窗 = InstantFlow 的第 0 步，不是独立组件

`InstantFlow.vue` 已有 card → invite → chat 状态机，心情小窗作为前置一步 `mood → card → …` 是最小改动：关闭/返回语义、覆盖层样式、与主页的挂载方式全部复用。四 chip（沮丧 / 烦躁 / 无聊 / 活力）+ 跳过项「都不是，随便来一件」。跳过项与 chip 同层展示、视觉权重不低于 chip（一等公民，不是角落小字）。

替代方案：独立 MoodSelect 组件——多一层组件通信，无收益，不采纳。

### D2 心情选择只存活在本次 InstantFlow 会话内

mood 存组件 data，流程关闭即弃。不写 storage、不进 analytics 载荷、界面上除小窗本身外不出现任何心情文案回显（同"数值不可见"纪律）。再次进入即时入口小窗重新出现、无记忆预选。

### D3 内容侧字段：`gate0: "A" | "B"`（可选），启动成本零字段派生

- **`gate0`**：条目通过 Gate 0 条件三的路径——A 类感知重定向 / B 类边界内新鲜尝试。这是内容写作时已经存在的客观分类（content_principles Gate 0），打标即誊写，一眼可判可审计。可选字段，缺省 = 中性，不参与心情软优先，永远可被抽中。字段名直接沿用原则文档的 Gate 0 术语，不发明新词。
- **启动成本**：不加字段。由 `scene_tags` 派生——**就地场景**（`home / workspace / classroom / transit / driving`，人已身处其中即可做）vs **出门场景**（`walking / market / convenience-store / gym / canteen`，需要移动到位）。条目含任一出门场景视为"出门型"，只含就地场景视为"就地型"。派生表放纯函数里，与时段规则表同风格。

替代方案：给条目直接打心情标（`mood_affinity: ["沮丧"]`）——主观状态标注到客观事件上，打不准、无法审计、与"内容是中立客观事件"冲突，不采纳（这正是本变更立项时的核心讨论结论）。

### D4 心情→属性映射表（代码内，纯函数）

| 心情 | 相容判定（软优先置前条件） |
|---|---|
| 沮丧 | `gate0 === "A"` 且为就地型（低启动 + 感知舒缓） |
| 烦躁 | 同沮丧（路由一致，chip 分开只为让用户被准确叫出名字） |
| 无聊 | `gate0 === "B"`（缺的是新鲜刺激） |
| 活力 | 出门型（趁能量在，把平时抽不动的抽出来；不看 `gate0`） |

实现为 `preferMoodCandidates(candidates, mood)`，放 `momentInference.js`（同属"即时抽取软优先"域，共享中性/回落语义与"规则表+纯函数"风格）。无 mood 或候选无相容条目时原样返回。

> **修订（2026-07-17 真机验收，3.11 活力失灵）**：两处修正。① "出门型"判定收紧为**含出门场景且不含任何就地场景锚点**（general 不算锚点）——原"沾一个出门场景即相容"让 15 条就地感知类混合打标条目（如 [walking,home] 的看天空）占满活力层，池内大宗盖过真出门条目；收紧后活力层 40→26 条，全部为真需挪地方的条目。② 活力时候选获取**跳过时刻推断收窄**、直接按档案 scene_tags 抽——推断偏就地（深夜=home 等），会在获取层就把真出门条目挡在 12 条窗口外，D5 的"显式>推断"只作用于排序层压不过它；此修订把该层序兑现到获取层。既有边界不变：档案 scene_tags 不含任何出门场景时活力自然透传（内容从不推荐档案外场景，与心情层无关）。

### D5 叠加顺序：mood 软优先在 moment 软优先之外层

`preferMoodCandidates(preferMomentCandidates(candidates, now, weather), mood)`——两次都是稳定分层（相对顺序不变），结果等价于"先按心情相容分大层，层内保持时刻优先序"。理由：心情是用户**显式说出**的信号，权重应高于系统**推断**的时刻信号。

### D6 呼吸直通：沮丧/烦躁二段式，无聊/活力直抽

- 点「无聊」「活力」或跳过 → 直接进任务卡（软优先已生效），与现状步数一致。
- 点「沮丧」「烦躁」→ 小窗内过渡为两个去向：「来件轻的小事」（进任务卡）/「先静一下」（emit 事件由 index.vue 打开既有 BreathingGuide 覆盖层，InstantFlow 关闭且不留任何记录）。理由：对这两种心情，呼吸可能比任务更对（反馈⑧原话即"推深呼吸"），值得多一步诚实的分岔；两个选项都是去向不是配置，不构成负担。

替代方案：任务卡内放呼吸小链接——太隐蔽，等于没给；四 chip 下常驻"先静一下"——对无聊/活力是噪音。均不采纳。若内测反馈二段式烦，可降级为任务卡内链接（改动局部）。

> **修订（2026-07-17 真机验收）**：用户反馈二段式确有打断感，执行预留降级——四心情均直抽任务卡；沮丧/烦躁时任务卡"做完啦"下方出「或者，先静一下」链接（复用 back-link 样式，触点足），点击仍走 emit `breathe` → BreathingGuide 的零记录通道。"太隐蔽"的顾虑被真机手感证伪：链接紧贴主按钮而非藏在角落，且只对沮丧/烦躁出现，不构成噪音。

### D7 验证：扩展 `scripts/verify-momentInference.mjs`

新增断言组：四心情映射正确性、无 mood 原样返回、无相容条目原样返回、gate0 缺省中性、就地/出门派生表与 scene 枚举一致（防新增 scene 漏归类）。不新建脚本。

## Risks / Trade-offs

- [池小分层后某心情层候选极少（69 条 × A/B × 场景），重复感加快] → 软优先不是过滤，层内耗尽自然退回全候选；内容侧用「熟悉载体 × 一个陌生变量」公式（已入 content_principles）低成本补 B 类，A 类就地型本就是池内大宗
- [沮丧/烦躁二段式多一步，可能被读成打断] → 两个选项均为单击去向；若内测反馈差，降级为任务卡内链接（D6 已预留）
- [gate0 边缘条目 A/B 难判（既有感知重定向又有新尝试）] → 同 moments 打标准则：含糊就不打，缺省中性；错标最坏结果只是软优先失效
- [「零决策抽取」的既有承诺被小窗动摇] → spec 层面显式改写该 requirement：跳过一等公民 + 跳过路径行为与现状逐字一致，"零决策"从"无任何界面"收窄为"无必须做的决策"

## Migration Plan

纯前端增量，无数据迁移、无云函数改动。部署即生效；回滚 = 回退前端版本（无持久化状态残留，mood 不落库）。依赖顺序：add-instant-moment-fit 先归档（spec 基线），实现层无硬依赖冲突（代码已在同一基线上）。
