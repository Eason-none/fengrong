## 1. 一页概览（TL;DR）

**一句话定位**：
> 「人类丰容指北」是给 16–26 岁、生活被学业/工作/信息流塞满、对生活感到无聊、疲惫和无意义的学生与职场新人的一个慢节奏微信小程序——把动物园的"环境丰容"学科方法迁移到人身上，用嵌在日常动线里的非功利小事，帮用户把真正属于自己的时间拿回来，重新体会"存在本身可以是轻松愉快的"。

**与替代品的区别**（一句话版）：
- 对冥想/正念类：它们做减法（平复情绪、消除难受），丰容做加法（创造乐趣与意义）——目标不是"不难受"，而是"重新觉得生活有意思"
- 对抖音/小红书：同样填充闲暇时间，但方向相反。"多巴胺轰炸"已经是用户自己的吐槽——大家知道一味刷不好，只是没找到替代品。丰容做的就是那个慢节奏替代品：从屏幕里的无限流，换成真实世界里的一件小事

**三个亮点**（HR 只看这里）：
- 从动物行为学的"环境丰容"理论出发做产品定位，不是又一个打卡/冥想 App 的模仿品
- 全程 spec 驱动开发（15 次归档变更记录），每个功能上线前有提案、设计、验收清单，砍过 2 个大功能
- 7 位真实用户内测 + 两轮反馈迭代已完成；AI 能力有明确的使用边界和内容质量治理（Gate 0/Gate 1 准入）

**演示方式**：微信体验版可现场真机演示（正式版审核中）；另备 60 秒核心流程录屏。
【占位：体验版二维码 / 录屏链接】

## 2. 项目背景与整体思路

### 2.1 为什么做这个

三个观察，一个顿悟。

**观察一：AI 时代的信息环境在系统性地煽动焦虑。**替代恐慌、成功学、"再不学就晚了"——信息流的商业模式决定了它奖励煽动性内容，而年轻人是被浸泡最深的一代。

**观察二：生活本身在功绩化。**工作被卷入生活甚至家庭，学业、绩效、亲密关系全都变成待优化的项目，人处在持续耗竭中。哲学一点说：存在与休闲本身被遗忘了，或者说被消费主义异化了——"休息"变成了刷内容和买东西，真正留给自己的时间趋近于零。

**顿悟时刻**：我看到一个说法——人类无意识地刷短视频，本质上就是圈养动物的刻板行为（stereotypy）。这句话把问题重新诊断了：如果症状是刻板行为，那么解法不是"治疗这个人"，而是改造环境——而环境改造恰恰是动物园行为学里一套已经成熟了几十年的方法论：环境丰容。人类还没有自己的丰容产品，这就是空位。

**为什么冥想 App 填不上这个空位**：冥想类产品回答的是"怎么让自己不难受"，但无聊、疲惫、无意义感的反面不是平静，是乐趣和意义。没有产品在回答"怎么重新觉得生活有意思"——这是本产品的立足点。

### 2.2 理论底座：动物丰容 → 人类丰容

动物园行为学里的"环境丰容"（environmental enrichment）：圈养动物出现刻板行为，不是因为缺食物，而是因为环境剥夺了它的感知和探索。解法不是"治疗动物"，而是改造环境——藏起食物让它找、引入新气味、改变空间结构。

产品映射：现代年轻人的"圈养环境"是算法信息流 + 两点一线动线。产品不做情绪治疗（那是心理咨询的领地），只做环境改造——把"轻微陌生感"的小事嵌回用户已有的生活动线里。

**由此推出的两条内容铁律**（content_principles.md 原则一/二，全部内容生产受其约束）：
1. **感知必须真实发生**——每件事必须让用户真实地看到/听到/摸到什么，不接受纯心理活动
2. **轻微陌生感、无表演压力**——离日常一步远，但不需要任何人观看

### 2.3 整体思路（产品观）

三个贯穿始终的立场，后文所有决策都能回溯到这里：

- **反打卡**：不设连续天数、不设未完成红点、任务不过期。丰容不能变成新的 KPI，否则就成了它要解决的问题本身。
- **零决策**：焦虑时刻的用户没有决策能量。所有入口的选择步骤能删则删（详见案例 4.1、4.2）。
- **数值不可见**：不做情绪打分、不做统计图表、不形成情绪档案。产品知道得越少，用户越安全（详见第 9 节 AI 边界）。

## 3. 问题定义与优化点发现方法

这一节回答"你作为 PM 是怎么工作的"，方法本身是作品的一部分。

### 3.1 问题如何被定义

不从"用户要什么功能"出发，从"用户处在什么状态"出发。产品识别三种状态并分别给出供给：

| 用户状态 | 供给 | 对应能力 |
|---|---|---|
| 情绪被击中的那一刻（被信息流淹没、烦躁发闷），需要立刻被接住 | 呼吸引导 + "现在就来一件"零决策抽取 | breathing-entry, instant-task |
| 日常动线无聊，需要非功利小目标 | 地球 Online 日推卡片 + 领取制任务 | daily-card, daily-tasks |
| 想要更深的探索和累积感 | 图鉴收集 + AI 回顾叙事 | collection-review, trace-reencounter |

### 3.2 优化点如何被发现（三个输入源）

1. **理论推演**：丰容五维度逐一对照产品覆盖面，找结构性缺口（例：心情适配的立项起点是"抽取对用户内部时刻一无所知"这个理论盲区）
2. **内测反馈**：第一批内测用户反馈 → 归类为"功能对、体验糙"的摩擦点清单 → 两轮 polish 变更集中修（呼吸节奏跟不上、输入框贴键盘、AI 收束生硬等 9 项）
3. **机制自审**：定期用"这个机制对结果有硬性影响吗"反问既有设计，砍掉答案为否的（例：场景三选交互被砍，见案例 4.1）

**内测的实际情况**（照实写，小数字不修饰）：备案等待期内邀请 7 位朋友真机内测，反馈通过微信直接收集。反馈分两类：功能体验建议（其中分量最重的两条：AI 回复慢且等待时毫无反馈、呼吸引导无法跳过——均已闭环，见案例 4.3）和 bug 反馈。7 个人不构成统计显著性，但足够暴露体验层的结构性摩擦——内测阶段要的本来就是摩擦点，不是转化率。

### 3.3 流程工具

每个变更走 openspec 流程：提案（Why/What/Impact）→ 设计 → 分解任务 → 实现 → 真机验收清单逐项过 → 归档进主 spec。截至目前累计 15 次归档变更、17 个能力的活文档。

## 4. 核心设计决策案例（功能点，按决策组织）

> 写法说明：每个案例 = 背景 → 我面对的选项 → 我选了什么、砍了什么 → 为什么。截图为证据，决策是主角。

### 案例 4.1 砍掉"场景三选"主交互——减法比加法难

**背景**：早期版本里，用户每次进入都要先在"室内短/室内久/室外"三个场景里选一个，再收到匹配的推送。这是主页主流程。
**发现**：场景信息其实是档案级的（用户的通勤方式、常去地点很少变），让用户每次都选，是把系统该做的事转嫁成用户的决策负担——和"零决策"立场直接冲突。且它导致双内容池、双去重机制的无谓复杂度。
**决策**：整体删除场景三选交互和它背后的推送层机制（含 38 条已上线内容的重新打标迁移），改为"现在就来一件"按钮：点一下，直接给一件事。
**代价与取舍**：删掉的是已经做完并上线的功能。判断依据是"两池的内容准入标准完全相同，分开没有需求依据"——机制不能因为沉没成本而保留。
【截图：现在的主页"现在就来一件"入口】

### 案例 4.2 心情系统——"问"而不是"猜"，AI 的边界决策

**背景**：即时抽取对用户此刻的心情一无所知：烦躁的人可能被派去菜市场买不认识的菜，一次错配就会让入口被读成"随机老虎机"（内测原话方向：心情不好时呼吸、听歌类更实用）。
**选项**：A. 用 LLM 从行为数据推断用户情绪；B. 直接问用户；C. 不做。
**决策**：选 B，且加三条纪律——
1. **跳过是一等公民**："都不是，随便来一件"和四个心情 chip 平级展示，不选不惩罚，行为与没有这个功能时完全一致
2. **内容不打心情标**：心情是主观的，内容属性是客观的。代码里维护"心情→客观属性"映射表（无聊→新鲜尝试类；沮丧/烦躁→低启动成本+舒缓类；活力→出门/移动类），内容侧只打客观可审计的标
3. **不留痕**：心情选择不持久化、不进统计——这不是情绪追踪 App，用户的情绪不该成为数据资产
**为什么不选 A**：推断情绪意味着建立情绪画像，与"数值不可见"立场冲突；且推断错误的代价（用户感到被误读）远高于收益。**知道哪里不用 AI，和知道哪里用，是同一种能力。**
【截图：心情小窗，四 chip + 跳过】

### 案例 4.3 内测反馈迭代——从"功能对"到"体验对"

**背景**：7 位内测用户的反馈集中在体验摩擦，其中分量最重的两条批评，处理方式恰好体现两种不同的 PM 判断：

**批评一："呼吸引导无法跳过"——修的不是按钮，是控制权归属。**
最初的设计假设是"用户需要先安顿下来再进入产品"，强制呼吸前置。内测证明这是产品的一厢情愿。修复分三层：呼吸引导仅首次启动出现且可跳过；改为主页常驻"静一下"自选入口（无角标、无使用记录、不产生任何"你该做呼吸"的暗示）；引导进行中新增低调的"先不做了"退出，**且明确规定不加任何挽留弹窗**——挽留本身就是压力，和这个产品的存在理由冲突。教训写进了产品观：控制权永远在用户手里。

**批评二："AI 回复太慢"+"等待时没有任何感觉"——把一条抱怨拆成两个问题。**
内测反馈里这两句经常连着出现，但它们是不同的问题：**慢**是硬约束——微信小程序端无流式输出，长回答等待可达十几秒，短期无法根治；**没感觉**是设计缺陷——等待期间界面完全静止，用户无法区分"AI 在想"和"卡死了"。前者诚实面对：不假装能修好，流式方案列入后续技术规划；后者立即修：先给"···"输入指示（对面在打字的心智），等待超约 8 秒再淡入一句轻等待语，更久换一句——反馈随时间升级，静默永不出现。**能把用户的一句抱怨拆解成"约束"和"缺陷"分别处理，是比修 bug 更重要的判断。**

**其余打磨**（两轮 polish 共 9 项，再挑两个有判断含量的）：
- 呼吸节奏跟不上：加"随秒数柔和点亮的节奏点"而**明确不用数字倒计时**——倒计时是压力语言，与产品气质冲突
- AI 摘要生硬、收束突兀：不改架构，改 prompt——原话定位从"拼接的积木"改成"引用的素材"；"至多追问一次"这类**次数型硬规则**改写为**能量匹配式渐进描述**。对 LLM 产品，prompt 的措辞方式就是产品设计本身
【截图：呼吸引导节奏点 + "先不做了"入口 / 一段自然的 AI 摘要】

### 案例 4.4 订阅提醒——平台约束下的机制设计

**背景**：产品反打卡，但完全无触达则会被遗忘。微信小程序的订阅消息是一次性授权制（用户授权一次，只能发一条），这是硬约束。
**决策**：把"请求授权"挂在用户的高频自然动作之后静默攒额度，而不是弹窗乞求；提醒文案定稿为「记得留一些时间探索世界哦~」——是邀请不是催促；提醒时间 5 分钟颗粒度对齐发送侧扫描窗口。
**取舍**：宁可触达率低，不做打扰式弹窗——触达设计必须服从产品气质。
【截图：提醒设置页】

### 案例 4.5 内容质量治理——AI 时代的内容供应链

**背景**：内容池 69 条 + 图鉴 8 本，部分由 AI 辅助生产。AI 能无限生成内容，所以稀缺的不是产能，是**准入标准**。
**决策**：成文的两道门——
- **Gate 0（质量门）**：具体可执行 / 不说教 / 有陌生感 / 处境优先于注意力指令，四条全过才存在
- **Gate 1（分层门）**：≤5 分钟、不挑场景的进推送层；有情境依赖、更深的进图鉴层
- 配套可复用的写作公式（如新鲜尝试类 =「熟悉载体 × 一个陌生变量」），让标准可传递、可审计

## 5. 产品架构

### 5.1 功能架构

```
                        ┌─ 用户档案（玩家ID / 场景偏好 11 维标签）
                        │
  ┌─────────────────────┼──────────────────────────┐
  │ 即时轨道             │ 日常轨道                  │ 深度轨道
  │ 焦虑那一刻           │ 每天打开时                │ 主动探索时
  │                     │                          │
  │ 呼吸引导(4-7-8+海浪) │ 地球Online日推卡片        │ 图鉴收集(8本)
  │ 现在就来一件         │ 每日3个候选任务·领取制     │ 条目解锁/完成
  │  ├ 时刻推断(时间/天气)│ 任务不过期·无未完成态      │ 100% → AI回顾叙事
  │  └ 心情软优先(可跳过) │                          │
  └─────────────────────┴──────────────────────────┘
                        │
              完成事件 → 可选AI对话（聊聊）→ 摘要 → 日记痕迹
                        │
              日记本 / 痕迹重逢 / 三件幸福小事 / 分享卡(3版式×5纸样)
```

### 5.2 内容架构

- 每日任务池（69 条，11 维场景标签 + Gate 0 类别标）——供即时抽取与日推候选
- 图鉴层（8 本图鉴）——深度内容，条目制解锁
- 全部内容过 Gate 0/Gate 1 准入（见案例 4.5）

### 5.3 技术架构（一段话即可，面试官关心的是你懂不懂边界）

uni-app（Vue3）→ 微信小程序端；数据本地存储优先（与"数值不可见"的隐私立场一致）；LLM 调用经自建云函数代理（密钥不落客户端、可控模型切换与限流）；订阅消息经云函数定时扫描发送。
✍️ **待你确认**：这段深度对 AI PM 岗够用，如果目标岗位偏技术可再展开 LLM 代理的设计考量。

## 7. 原型 → 最终效果：三次公开的自我否定

> 这一节不放"原型图"，放**被推翻的设计**。v1 spec 里三个当时确定的机制，全部在后续版本被砍掉，砍它们的理由比做它们的理由更能说明判断力。

| v1 原型设计 | 最终形态 | 为什么改 |
|---|---|---|
| 解锁名额经济系统（做任务赚名额→消耗名额解锁图鉴，含 50% 进度返还名额的棘轮） | 固定 3 个激活上限 + 随时放下 | 名额是游戏化的稀缺性设计，但稀缺性制造的是焦虑——和产品目的正好相反。资源系统整体移除 |
| 每次进入选场景（室内短/室内久/室外三选） | 档案级 11 维场景标签，进入即抽取 | 把系统该做的匹配转嫁成了用户的决策负担（详见案例 4.1） |
| 对话"归档按钮 + 每 5 条消息弹确认" | 常驻「说完了」+ 固定收尾文案 | 打断式确认是系统在赶用户走；控制权应始终在用户手里且不打断 |

**共同模式**：三个被砍的设计都是从"别的产品这样做"（游戏化经济、个性化前置提问、会话管理）类比来的，而不是从"焦虑的用户此刻需要什么"推出来的。类比引入的复杂度，最终都被第一性原理清算。

## 9. AI 使用边界（AI PM 专项）

| 用在哪 | 怎么用 | 为什么敢用 |
|---|---|---|
| 完成后对话（聊聊） | 云函数代理调用 LLM，prompt 里写入产品气质约束 | 有 prompt 治理：次数型规则改能量匹配式、收束必须有过渡（案例 4.3） |
| 完成摘要 / 图鉴回顾叙事 | 用户原话作为"引用素材"生成 | 摘要只消费用户主动说出的内容 |
| 内容生产辅助 | AI 辅助写内容条目 | 全部过 Gate 0/1 人工准入（案例 4.5） |

| 坚决不用在哪 | 为什么 |
|---|---|
| 推断用户情绪 | 用问的，不用猜的；不建情绪画像（案例 4.2） |
| 情绪数据统计/追踪 | 数值不可见原则；产品知道得越少用户越安全 |

**一句话立场**：这个产品里 AI 的角色是"听者"和"叙述者"，不是"分析者"。

## 10. 商业化思考

**倾向路径：内容包扩展。**用户一次性购买主题图鉴内容包（例：城市探索、季节限定、通勤特辑），扩展探索素材。

**为什么是内容包而不是订阅或广告**：
- 内容包与产品调性自洽——用户是在为"新的探索素材"付费，像买一本新图鉴，是价值加购；订阅制天然携带"这个月没用回本"的隐性压力，和反打卡立场直接冲突
- 广告从一开始就被排除：内容准入 Gate 0 要求"不说教、无表演压力"，而广告的本质是注意力再售卖——把用户从信息流里接出来再卖回给信息流，产品就失去了存在理由
- 内容包路径还有一个结构优势：它逼迫内容质量持续在线（Gate 0/1 治理体系是它的供应链），付费意愿直接验证内容价值

**为什么现阶段刻意不做**：信任在先。产品的立身之本是"这里没有人想从你的疲惫里赚钱"；在留存和图鉴完成率被真实数据验证之前加付费墙，既伤信任基础，也没有数据支撑定价。商业化的前置条件写死为：图鉴完成率与自然回访数据证明内容是被真实消费的。

✍️ **待你确认**：以上推理是基于你"倾向内容包"的口径起草的，逻辑是否符合你的本意？特别是"前置条件"那句，面试被追问"什么时候开始收费"时就用它回答。

## 11. 上线后的验证计划

> 这一节展示的是运营能力：埋点已就位（analytics-events），指标各自绑定要验证的假设，上线后按数据驱动迭代——把"还没上线"翻译成"运营与验证设计已就绪"。

**核心假设**：轻微陌生感的小事 + 零压力机制，能让用户在没有打卡激励的情况下自发回来。

**关键指标**（已有 analytics-events 埋点能力支撑）：
- 即时入口使用率：打开后点「现在就来一件」的比例——验证"焦虑时刻被接住"是否真实发生
- 领取→完成转化：领取的任务最终完成的比例——验证内容是否"具体可执行"
- 心情小窗跳过率：如果 >80% 跳过，说明心情适配是伪需求，应考虑移除（预设移除条件，不是只准备庆祝）
- 7 日回访：无提醒自然回访 vs 订阅提醒带来的回访占比
- 聊聊转化率：完成后进入对话的比例——AI 对话是价值点还是摆设

**迭代机制**：指标不是仪表盘装饰——每个指标绑定一个假设，数据到位后按"假设被证实→加深投入 / 假设被证伪→修正或移除"驱动版本规划（心情小窗那条已预设了移除条件，对自己的设计保持可证伪）。
